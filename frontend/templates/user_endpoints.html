Request schema
Exactly one node must be Text. Source and Target Language are optional. A Context list node is optional too: when present it sends the earlier [[source, english], ...] pairs with the request, so the API can keep tone and names consistent. Character Info and Context Links list nodes are optional as well: the first sends the character roster ([{meta_id, name_en, name_ja, gender, alias_en, alias_ja}, ...]), the second one speaker id (or null) per context pair, so the API can attribute each turn. The two always go together — a schema with one must have the other — and either node can sit under any field name. Static strings accept the placeholder tokens. A uuid field mints a fresh identifier per request — pick the variant in its value box. Prefer uuid4: it is pure randomness, while uuid1 puts this machine's network address in every request.
Dynamic nodes are filled in per request; static values are sent unchanged.
Response schema
Exactly one node must be Translated Text. Error and Alternatives are optional. Add a repeat template to a list when the reply splits the translation across an unknown number of chunks.
The Translated Text node becomes the translation; Alternatives are listed under it.

Encryption
Optional, and off unless a key is given. When on, the selection is sealed before it leaves this machine and the reply is opened after it arrives, so a proxy, a middlebox or a request log carries a token instead of what is being read. The endpoint holds the same key and reverses it, which means this hides the text from the network — not from the API itself.
